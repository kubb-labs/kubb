Add the `from(source?)` composable and the `code` template. `from(plugin).resolver` wraps a plugin's resolver, so each resolver method that returns a name returns the name plus its import from that plugin's file. A schema name that is not in the document, or a node the plugin excludes, gives no import. `from(plugin).has(node)` tells whether the plugin generates `node`. `from(plugin).import(node, name)` imports any name from the plugin's file for `node`. A resolver's new `file.name` names the files it writes, and `file()` and `from()` both read it, so callers pass only the node. The `Operation` suffix for an operation file that would land on a schema file now applies only to a plugin with a schema generator. `file({ name })` returns the props for a file that no single node owns, such as an index of every operation. `provide(name, factory, { priority })` offers a resolver under a shared name, such as `'types'`, and `from(name)` and `getResolver(name)` read the provider with the highest priority. `code` returns the text and the imports of the names in its placeholders, grouped per path. `code.join` joins several parts.
